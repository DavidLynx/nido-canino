Workflow — Website Maintenance Plan
Purpose

This workflow helps Lynx Visual Division create, sell, organize, and execute monthly maintenance plans for websites, landing pages, catalogs, portfolios, and lightweight web apps.

Use this workflow when a client needs:

website updates
product/catalog updates
content changes
SEO improvements
performance checks
bug fixes
mobile improvements
visual polish
monthly reports
contact form checks
campaign support
ongoing optimization
technical support within a defined scope

The goal is to create recurring revenue without offering unlimited work.

A good maintenance plan should be:

clear
realistic
limited in scope
easy to explain
easy to renew
useful for the client
protective of Lynx Visual Division’s time
connected to business value

Phase 1 — Maintenance Fit Check
Goal

Decide if the project is suitable for a maintenance plan.

Good Fit Signals

A maintenance plan is useful when:

the client updates content regularly
the site supports sales or leads
the client has products/services that change
SEO matters
the site needs ongoing polish
the client does not want to handle technical changes
the site needs periodic performance checks
the client wants monthly improvements
the website is an active business asset
Poor Fit Signals

Avoid or be careful when:

the client expects unlimited work
the client wants emergency support for a low monthly fee
the website is technically unstable
the platform is outside current skill/capacity
the client needs complex backend support
the client expects legal, medical, financial, payroll, or regulated content responsibility
the client does not provide content on time
the scope is vague

Phase 5 — Pricing Logic
Goal

Price maintenance without undervaluing time.

Agents

Internal Formula

Use this logic:

Monthly price = estimated hours × hourly target rate + management buffer + complexity buffer

Buffers

Use:

management buffer: 10% to 25%
platform complexity buffer: low, medium, high
urgency buffer if response time is short
risk buffer for unclear scope
Quality Rule

Maintenance must be profitable.

If the price does not protect time and energy, reduce scope or increase price.

Phase 12 — Boundaries and Risk Control
Goal

Protect the studio from unclear or risky work.

Boundaries

Do not include by default:

unlimited revisions
full redesign
new app features
database architecture
custom backend
legal responsibility
medical/financial/payroll claims
emergency support
third-party platform responsibility
paid ads management
large copywriting projects
professional photography/video
complex e-commerce operations
If Client Requests Out-of-Scope Work

Respond:

That is outside the current maintenance scope, but I can quote it as an additional task or separate improvement sprint.

If Client Requests Urgent Work

Respond:

I can review it as an urgent request. Since urgent support is not included in the current plan, I’ll confirm availability and the additional cost before making changes.

If Client Sends Unclear Request

Respond:

I can help with that. To make the update correctly, please send the exact text, image, page/section, and the deadline you need.

Quality Rule

Clear boundaries create better client relationships.

Final Rule

Maintenance is not “small random favors every month.”

Maintenance is a structured service that keeps a digital product useful, updated, trustworthy, and aligned with the client’s business goals while protecting the studio’s time and value.
