Workflow — Portfolio Case Study
Purpose

This workflow helps Lynx Visual Division turn finished projects, prototypes, demos, apps, landing pages, and client websites into professional portfolio case studies.

A project is not portfolio-ready only because it exists.

It becomes portfolio-ready when it clearly communicates:

what problem was solved
who it was designed for
what decisions were made
what role Lynx played
what stack was used
what makes the work valuable
what the user experience improves
what the visual system communicates
what the technical implementation demonstrates
what can be learned from the project

Phase 1 — Project Selection
Goal

Decide if a project deserves a full case study, a short portfolio card, or should stay as an internal experiment.

Portfolio Value Criteria

A project has strong portfolio value if it demonstrates at least one of these:

strong visual design
clear UX thinking
useful web app interaction
responsive implementation
AI-assisted workflow
brand adaptation
SEO or conversion thinking
technical problem solving
product thinking
motion or interaction design
catalog or content structure
client/business relevance
Project Status Levels
Featured Case Study

Use when:

project is polished
live URL works
visuals are strong
story is clear
user/business goal is understandable
screenshots look good
project represents the studio well
Standard Portfolio Entry

Use when:

project is useful but not flagship
live URL works
short explanation is enough
visuals are acceptable
story is simple
Experiment / Lab Entry

Use when:

project is exploratory
not fully production-ready
demonstrates technique, style, or interaction
has value as a creative/technical experiment
Archive / Not Ready

Use when:

project is broken
visuals are weak
story is unclear
live URL does not work
it needs polish before public presentation
