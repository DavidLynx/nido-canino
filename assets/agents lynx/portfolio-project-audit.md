Lynx Visual Division — Portfolio Project Audit
Purpose

This file defines the audit system for deciding how each existing project should appear in the Lynx Visual Division portfolio.

The goal is to avoid adding projects randomly.

Each project should be reviewed for:

visual quality
technical quality
mobile behavior
bilingual completeness
live URL status
portfolio value
business relevance
screenshot quality
case study potential
polish needed
honest project status

This file helps decide whether each project should be:

Featured
Standard
Experiment
Coming Soon
Needs Polish
Archive
Critical Rule

Do not present unfinished, broken, or weak projects as finished professional work.

If a project is useful but incomplete, label it honestly.

Use:

Prototype
Concept
Experiment
In progress
Coming soon
Case study pending

Do not use fake client claims, fake metrics, or fake business results.

2. Audit Categories

Each project should be evaluated in these categories.

A. Strategic Value

Does this project help Lynx sell a service?

Score from 1 to 5.

Consider:

Does it show a service Lynx wants to sell?
Does it help explain the studio’s capabilities?
Does it match future client needs?
Does it show business usefulness?
Does it support international positioning?
B. Visual Quality

Does it look strong enough?

Score from 1 to 5.

Consider:

typography
spacing
hierarchy
color
responsiveness
imagery
motion
polish
originality
premium feel
C. UX Quality

Is it easy to understand and use?

Score from 1 to 5.

Consider:

clarity
navigation
main action
onboarding
empty states
error states
mobile usability
user flow
interaction feedback
D. Technical Quality

Is it stable enough to show?

Score from 1 to 5.

Consider:

live URL works
no obvious crashes
build likely works
links work
assets load
no broken routes
no missing images
no visible internal notes
no major console-breaking behavior
E. Bilingual Quality

Does language work correctly?

Score from 1 to 5.

Consider:

Spanish complete
English complete
no mixed sections
UI labels translated
buttons translated
metadata if relevant
layout works with both languages

If the project is intentionally single-language for now, mark:

Not applicable for current version.

F. Portfolio Story

Can this project become a strong case study?

Score from 1 to 5.

Consider:

problem is clear
solution is clear
role is clear
stack is clear
before/after exists
screenshots would look good
process can be explained
future clients would understand its value

Which service does this project support?

3. Project Status Labels

Use one of these labels.

Featured

Use when:

project looks strong
live URL works
mobile is acceptable
project clearly supports a service
screenshots are strong
portfolio story is clear
Standard

Use when:

project is useful
not the strongest piece
still worth showing
may not need full case study
Experiment

Use when:

project explores style, interaction, or concept
may not be client-ready
has creative/technical value
should be labeled honestly
Coming Soon

Use when:

project does not exist yet
concept is planned
can appear as future roadmap
should not be presented as finished
Needs Polish

Use when:

project is promising but not ready
visual or technical issues exist
should be improved before featuring
Archive

Use when:

project does not represent current quality
project is broken
project has low strategic value
project should not be shown publicly yet
4. Scoring System

Score each project from 1 to 5 in:

Strategic Value
Visual Quality
UX Quality
Technical Quality
Bilingual Quality
Portfolio Story

Total possible score:

30 points

Score Interpretation

26–30:

Featured candidate

22–25:

Strong standard project or case study candidate after minor polish

18–21:

Show only if needed, or polish first

13–17:

Experiment or needs polish

Under 13:

Archive or do not show yet

Important:

A project can have high strategic value but low current polish. In that case, mark it as:

Needs Polish

not Featured.

12. Final Rule

The portfolio should show growth and capability, but it should not dilute the studio with weak work.

Every project included should answer at least one question:

What service can Lynx sell because of this?
What skill does this prove?
What client would care about this?
What story does this tell?
Does this make the studio look stronger?

If the answer is unclear, polish it, reframe it, or leave it out.
