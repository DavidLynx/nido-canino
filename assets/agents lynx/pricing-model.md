Core Pricing Philosophy

Lynx Visual Division should not compete only by being cheaper.

The studio should compete through:

strong visual quality
clear process
AI-assisted efficiency
bilingual capability
design + implementation in one service
strategic thinking
responsive delivery
portfolio-level presentation
practical business value

Pricing should be competitive compared to agencies in English-speaking markets, but not so low that the work becomes unsustainable.

Project price = base time value + complexity buffer + revision buffer + management buffer + risk buffer

Buffers
Complexity Buffer

Use when the project has:

custom UI
animations
bilingual structure
many sections
many assets
filters/search
API integration
SVG animation
responsive complexity
custom design system
client-specific branding

Suggested buffer:

low complexity: 10%
medium complexity: 20%
high complexity: 30% to 50%
Revision Buffer

Use when the client may request many visual changes.

Suggested buffer:

1 revision round: 5%
2 revision rounds: 10%
3 revision rounds: 15%
unclear revision expectations: 20%+
Management Buffer

Use for:

meetings
messages
file handling
client follow-up
deployment coordination
content organization
feedback cycles

Suggested buffer:

simple project: 10%
normal project: 15%
heavy communication: 20% to 30%
Risk Buffer

Use when:

scope is unclear
platform is unfamiliar
assets are missing
deadline is tight
client is disorganized
integrations are uncertain
third-party tools are involved
project has compliance concerns

Suggested buffer:

low risk: 0% to 10%
medium risk: 15% to 25%
high risk: 30%+

If risk is too high, reduce scope or decline.

Discount Rules

Discounts should be strategic, not emotional.

Only offer discounts when:

project has strong portfolio value
client provides high-quality assets
scope is simple
client can refer future work
client accepts reduced revision scope
client pays upfront
project helps enter a target niche

Do not discount when:

client is disorganized
scope is unclear
deadline is urgent
client wants many revisions
project is technically risky
client undervalues the work
maintenance expectations are vague

If discounting, reduce scope instead of only reducing price.

Payment Structure

For most projects, use:

50% upfront
50% before final delivery or before publishing

For small projects:

100% upfront can be appropriate

For larger projects:

40% upfront
30% after approved design direction
30% before launch

For maintenance:

monthly upfront

For urgent work:

upfront payment before starting

Important:

Do not start large projects without deposit.

Revision Rules

Every package should define revision rounds.

Example:

Starter: 1 revision round
Standard: 2 revision rounds
Premium: 3 revision rounds

Extra revisions:

charged separately
or moved into maintenance/add-on

Clarify:

A revision is a set of feedback delivered together, not unlimited ongoing changes.

Minimum Viable Pricing Rule

Before accepting a project, ask:

Does this price cover the estimated time?
Does it include revision and communication time?
Does it protect against scope creep?
Does it match the responsibility level?
Does the client understand what is included?
Is there potential for maintenance or future work?
Would I feel resentful doing this work at this price?

If the answer to number 7 is yes, change the price or reduce scope.
